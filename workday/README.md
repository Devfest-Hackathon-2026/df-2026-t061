# Workday — 新入社員の経験から知る仕事

「入社してから知る」を、「入社する前に知る」へ。就活生が企業や配属先を選び、仕事についての予想を社員の実体験と照合し、面接で確認する質問を見つけるWebアプリ。

## 公開URL

https://workday-516713493020.asia-northeast1.run.app

公開版はCloud Run・Firestore・Vertex AIで動作する。架空2社4回答を同梱し、新しい社員回答はFirestoreへ保存する。
2026年11月10日の公開検証では設問4問の生成・表示と原文比較を確認した。
公開時の検証で1回を使用し、追加生成は合計で残り3回、期限は2026年11月11日19:00（日本時間）。
既存PCのローカル生成枠は公開版への移行時に停止し、二重使用を防ぐ。期限後も生成済みの結果は同じ入力で閲覧できる。
希望条件と予想のメモはブラウザーごとに保存される。
公開終了時は scripts/CLOUD_STOP.md を参照する。

## 試し方

Node.js 22以上で `npm ci`、`npm run dev -- --port 3210` を実行し、http://127.0.0.1:3210/ を開く。クラウドの認証情報は通常のローカル起動には不要。

1. **企業を探す**から「みなも業務設計（架空）」を開き、職種を「開発」にする。「応募前の企業研究」の「企業研究を始める」を押す。
2. 最初の問いに、たとえば「新しい機能の実装」と予想を書いてから「社員の声を見る」を押す。S03の再現テストの経験が表示される。「導入支援」に切り替えると、同じ部署でも異なる2人の経験を確認できる。
3. **ミスマッチ診断**では、希望条件を社員の回答と照合し、下部の「面接で確かめたい質問」を確認できる。
4. 「企業研究を始める」で、対象企業の社員回答からサーバー側のVertex AIが最大5問を生成する。利用可能な実行枠が必要。同じ入力の保存済み設問は再利用する。学生の予想や確認メモはモデルに送らない。
5. 企業詳細の原文一覧・質問応答、希望条件との比較も利用できる。**社員として回答**から新しい実体験を登録すると、その配属先の企業研究に反映される。

## データと根拠

初期の架空2社4回答は `data/voices.json`。新規回答はサーバーの `.workday-local/voices/` に1回答1JSONで保存する。書き込みは一時ファイルからrenameする。ブラウザーを変えても同じサーバーで回答を共有する。学生の希望条件はそのブラウザーのlocalStorage。認証なしのローカル運用で、自由記述の完全な匿名化は保証しない。

データ取得と登録は `lib/voice-store.js` にまとめた。回答者には匿名のIDを付け、根拠を「回答者ID＋質問項目」で参照する。フィルター外のID・存在しないID・一致しない引用はGeminiの結果として表示しない。引用の存在を機械的に検証しても、その解釈の妥当性は保証できない。少数回答は少数と明示し、配属時期や案件による違いを原文から確認できる。

## Geminiと料金

`POST /api/insights` の通常動作は無課金のローカル原文検索・ルールによる照合。自由な質問への生成回答および各条件の分析と面談の質問生成は、別の明示操作でVertex AIのGemini 3.1 Flash-Liteを利用する。分析・質問案をまとめて1回で返す。企業、職種、部署で絞った原文だけを対象にし、情報がない条件は情報不足として扱う。検索結果とモデルの出力はUI上で区別する。

クラウド実行は標準で無効。実施する場合は事前に[料金](https://cloud.google.com/model-garden/pricing)と[クレジットの適用範囲・残高・期限](https://cloud.google.com/billing/docs/how-to/resolve-issues)を確認し、当該入力に対する個別承認を得る。以前のシミュレーション用承認は使わない。認証はサーバー側のgcloud。ローカルホストからの明示操作限定、プロジェクトは devfest-512005。入力プロンプト12,000バイト以内、出力最大2,048トークン。検索などの追加ツールなし。

承認後にのみ `.workday-local/inference/approval.json` に `project, model, digest, issuedAt`（時刻はUnixミリ秒）を記録する。digestはローカルの `POST /api/insights` が返す、対象企業・フィルター・質問・回答内容を含むプロンプトのSHA-256。30分以内の一致する承認のみ有効。モデル通信前に排他的な実行記録を保存し、失敗・再起動後も同じ入力を再送しない。利用統計は実行記録に保存する。希望条件の画面遷移、回答登録、原文検索、テストではクラウド生成を行わない。

## 検証と旧版

`npm test` と `npm run build`。Vertexの新機能は模擬応答で検証する。旧シミュレーションは feature/employer-four-steps（b05cfce）に保存済み。新しいトップページは新入社員の回答を中心に構成し、旧版のローカルデータには触れない。


### 回数を限定したクラウド検証

個別承認された検証では、ローカルの `.workday-local/inference/session.json` にプロジェクト・モデル・承認時刻・期限・合計10回の上限を記録する。実行枠は全企業で共有し、新しく登録した企業にも適用する。入力プロンプトは12,000バイト以内、出力上限は2,048トークン。開発起動と本番ビルド（npm run build → npm start）の両方で、実行前に排他的な枠を確保し、失敗も1回に数える。再起動時も回数は保持する。成功した設問はサーバーにも保存し、同じ資料では再生成せず再表示する。希望条件の分析と自由質問は、利用可能な枠がある場合に表示されるAI実行ボタンから開始する。セッションの承認情報・社員回答・実行記録はGit管理対象外。

## Cloud Run と Firestore

WORKDAY_STORE=firestore をサーバーに設定すると、社員回答は workday-voices、
生成結果・トークン記録は workday-attempts、実行枠は workday-config/inference に保存する。
Cloud Runのサービスアカウントに roles/datastore.user と roles/aiplatform.user を付与する。
認証はサーバーのApplication Default Credentialsを使い、ブラウザーに鍵を渡さない。
同じ入力の予約と残り回数の消費をFirestoreの単一トランザクションで確定してから
Geminiを呼び出す。トランザクションは1回で、モデルの再送は行わない。

初期企業データは data/voices.json をコンテナーへ同梱する。既存PC上の投稿や実行記録は自動アップロードしない。
node scripts/initialize-cloud.mjs は、このPCの残り回数と期限だけをFirestoreへ初回作成する。
既存の設定を上書きしないため、再実行しても実行回数はリセットされない。
公開時は最小0・最大1インスタンス、CPU 1・メモリー512MiB、リクエスト単位課金を設定する。
ホスティング・DB・ビルド・イメージ保管の従量費用はGeminiの回数制限の対象外。
認証を省略したMVPであり、掲載回答の修正・削除は管理者対応が必要。
